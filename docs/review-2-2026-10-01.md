The supplied review examined `52e0935` / tag `0.1.0`. The publication findings

## Runtime changes

| Finding | Resolution |
| --- | --- |
| A1 — manifest overly restrictive | Each entry is validated independently. An absent or broken editor entry does not suppress the frontend. Relative nested paths such as `css/app.css` and `js/app.js` are supported, including in editor URLs. Empty type lists and script-only frontend entries are accepted. Paths escaping `build/` are rejected. Only validated entries reach the shared Encore loader, so ignored invalid entries cannot cause a second-read failure. |
| A2 — excerpt compatibility | Card excerpts use `get_the_excerpt`, restoring native length, suffix and plugin filters. Reusable public blocks are expanded through the excerpt allowlist with cycle/depth protection; private/protected reusable content stays excluded. Metadata uses a separate render-free helper. Singular pages no longer compute an unused card excerpt, preserving the single body-render guarantee. |
| A3 — stale hierarchy | Hierarchy collection is local to each `candidates()` call. Native getters inspect the current query; capture filters are removed in `finally`, including after exceptions. There is no request-global candidate cache. `Renderer::render($candidates, $context)` supports explicit REST/AJAX/CLI rendering without querying the WordPress loop. |

Dynamic blocks follow the native `excerpt_allowed_blocks` policy. A custom block
must be opted in and must not recursively generate excerpts. The theme does not
automatically execute arbitrary forms, query loops or third-party dynamic blocks
to obtain card text. An authored excerpt remains the simplest choice for such
content. Public reusable blocks use that same allowlist for their contents.

## Other findings

- Fixed the misaligned nested menu arguments in Context and WordPressExtension.
  The shared formatter now leaves those arrays unchanged.
- No active `composer.local.json` remains. The obsolete local-release overrides
  were archived after public publication; current `composer.json` already
  requires `nikic/php-parser` directly for extraction.
- Font variables follow their theme.json slugs. Removed the generator's
  `display` → `heading` special case and updated CSS consumers.
- Token generation runs in webpack's `beforeCompile` hook. The compilation
  watches `theme.json`; importing the configuration alone writes nothing.
  `npm run tokens` is available for explicit generation.
- PHP translation extraction filters the `sympress-starter` domain. Twig helpers
  already bind that domain. Printf placeholders receive `php-format` flags;
  `scripts/extract-translations.php --check` verifies catalog freshness.
- Release instructions explicitly include `resources/views/` and
  `resources/css/`, including the fallback's generated token files.
- The current editor screenshot from the successful browser run is included.
- Composer invokes QA through `@php vendor/bin/qa`, keeping Composer's selected
  PHP binary for child processes. The global image PHP alternative is unchanged.
